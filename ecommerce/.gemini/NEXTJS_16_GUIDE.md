# Next.js 16 & React 19 Project Guide

This guide outlines the modern standards and architectural patterns for the **Boutique Diary** project, focusing on Next.js 16, React 19, Tailwind CSS 4, and Prisma.

## 🚀 Core Architecture: Next.js 16 + React 19

### 1. Server-First Mentality

- **React Server Components (RSC):** Use by default for all data fetching and layout structure.
- **Data Fetching:** Prefer `async/await` directly in Server Components using `prisma`.
- **Minimal Client JS:** Only use `'use client'` for interactive elements (forms, carousels, modals).

### 2. React 19 Features

- **Server Actions:** Use for all mutations (POST/PATCH/DELETE).
- **`useActionState`:** (formerly `useFormState`) The standard for handling form submission status and validation errors in Client Components.
- **`useOptimistic`:** Use for immediate UI feedback in the cart and wishlist.
- **`use` API:** For un-wrapping promises or context in Client Components.

## 🛠️ Data Mutation: Server Actions Pattern

### Standard Form Action

```tsx
// src/app/actions/product-actions.ts
"use server";
import { revalidatePath } from "next/cache";

export async function updateProduct(prevState: any, formData: FormData) {
  try {
    // 1. Validate with Zod
    // 2. Mutate with Prisma
    // 3. Revalidate
    revalidatePath("/admin/produits");
    return { success: true };
  } catch (e) {
    return { error: "Failed to update" };
  }
}

// src/components/ProductForm.tsx
("use client");
import { useActionState } from "react";
import { updateProduct } from "@/app/actions/product-actions";

export function ProductForm() {
  const [state, formAction, isPending] = useActionState(updateProduct, null);

  return (
    <form action={formAction}>
      {/* Inputs */}
      <button disabled={isPending}>Save</button>
      {state?.error && <p>{state.error}</p>}
    </form>
  );
}
```

## 🎨 Styling: Tailwind CSS 4

### The `@theme` Block

Tailwind 4 uses a CSS-first configuration. Use the `src/app/globals.css` `@theme inline` block for custom design tokens.

### Theme Variables for Boutique Diary

Refer to `design-system/boutique-diary/MASTER.md` for specific color palettes.

- **Primary:** `oklch(0.205 0 0)` (Stone 900 equivalent)
- **Accent:** `oklch(0.708 0 0)` (Gold/Bronze tones)

## ⚡ Performance & Optimization

### Image Strategy

- Use `next/image` for all non-base64 images.
- Prefer `NgOptimizedImage` patterns where applicable in Angular contexts, but in Next.js, use `priority` for Hero images.

### Caching

- Use `revalidatePath` and `revalidateTag` inside Server Actions to keep the UI fresh without full page reloads.
- Leverage `unstable_cache` for expensive Prisma queries.

## 🗄️ Database: Prisma & PostgreSQL

- Keep the `PrismaClient` singleton in `src/lib/prisma.ts`.
- Use **Transactions** for complex orders (Inventory check + Order creation).
- Always include `createdAt` and `updatedAt` in new models.
